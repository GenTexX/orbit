# Script pipeline: single-pass WASM emission, wasmtime, refcounting in linear memory

The script compiler is lex -> parse -> type-check -> emit WASM directly from the typed AST (wasm-encoder), with no optimizing middle-end: compile speed is achieved by skipping optimization entirely and letting the engine's JIT optimize at module load. Execution is wasmtime (Cranelift JIT - near-native game-loop speed, millisecond loads for script-sized modules; wasmi's faster startup wasn't worth its 10-50x slower steady state). Memory management is compiler-emitted reference counting over a free-list allocator in linear memory (Swift's model): deterministic, no GC pauses, simple to debug. Known limitation: reference cycles leak until weak refs / a cycle collector exist. WasmGC was rejected as newer, rougher in wasmtime, and opaque to debug; a hand-written tracing GC was rejected because WASM's lack of stack introspection forces shadow stacks - a months-long detour.
